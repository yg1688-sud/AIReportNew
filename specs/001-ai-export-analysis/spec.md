# Feature Specification: AI 导出与分析系统（AIExport）

**Feature Branch**: `AIExportNew`

**Created**: 2026-06-22

**Status**: Draft

**Input**: 用户描述：实现系统集成导出和分析模版，导出后直接进行按选定模版分析，给出分析结果。全部操作由后端实现，不需要前端介入。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 配置化数据导出 (Priority: P1)

作为系统管理员，我希望通过配置文件定义 SQL Server 查询语句和连接参数，系统能自动执行查询并将结果导出为标准格式（.xlsx），以便后续分析使用。

**Why this priority**: 数据导出是整个流程的入口，没有数据导出就无法进行任何后续分析。这是 MVP 的最基础能力。

**Independent Test**: 配置一条 SQL 查询，启动导出任务，验证系统成功连接 SQL Server、执行查询并生成 .xlsx 格式的结果文件。

**Acceptance Scenarios**:

1. **Given** SQL Server 连接配置和查询语句已配置，**When** 系统触发导出任务，**Then** 系统成功连接数据库并执行查询，将结果保存为 .xlsx 文件。
2. **Given** SQL Server 连接失败（网络不通/认证错误），**When** 系统触发导出任务，**Then** 系统返回明确的错误信息（包含失败原因），不产生空文件或脏数据。
3. **Given** 查询结果为空（无匹配数据），**When** 系统执行导出，**Then** 系统生成空结果集文件并记录"无数据"日志，不报错。
4. **Given** 配置文件中的查询语句包含参数化占位符（日期范围、企业ID等），**When** 系统执行导出，**Then** 系统将参数替换为实际值后执行查询。
5. **Given** 配置文件不存在或格式错误，**When** 系统启动导出，**Then** 系统返回明确的配置校验错误，指出具体问题行。

---

### User Story 2 - 模版化数据分析 (Priority: P1)

作为业务分析师，我希望系统能将导出的原始数据按选定分析模版的格式进行匹配和计算（汇总、排序、占比），生成结构化的分析结果表格。

**Why this priority**: 分析模版是核心业务价值所在——将原始数据转化为业务洞察。与数据导出同为 P1，两者共同构成 MVP。

**Independent Test**: 提供一份导出的原始数据和一份分析模版定义，运行分析引擎，验证输出结果包含按模版格式排列的数据行，且汇总值与占比计算正确。

**Acceptance Scenarios**:

1. **Given** 导出的订单明细数据和"三诊九体培训动销"分析模版，**When** 系统执行模版分析，**Then** 系统按门店+员工维度汇总销售金额，生成包含序号、片区、门店、姓名、员工ID、销售金额、部门的分析表。
2. **Given** 导出的订单数据和总销售额查询结果，**When** 系统计算占比，**Then** 每个员工的销售占比 = 员工销售额 / 连锁月度总销售额 × 100%，所有员工销售额之和与"合计"行匹配，总占比接近 100%。
3. **Given** 导出数据中有员工在模版中不存在，**When** 系统执行模版匹配，**Then** 系统将未匹配员工在附录中单独列出并记录日志，不计入合计行和总销售额。
4. **Given** 模版中定义的员工在导出数据中没有销售记录，**When** 系统执行模版匹配，**Then** 该员工的销售金额显示为 0，保留在结果表中。
5. **Given** 模版定义了多级分组（片区→门店→员工），**When** 系统执行分析，**Then** 结果保持模版的层级结构，小计在分组级别正确计算。

---

### User Story 3 - 分析结果导出与报告生成 (Priority: P2)

作为业务管理员，我希望系统将分析结果导出为 Markdown 分析报告和 Excel 表格，报告包含标题、日期范围、汇总统计和详细分析表格，以便分发和存档。

**Why this priority**: 在数据导出和分析能力就绪后，报告生成将分析结果转化为可交付的业务文档。

**Independent Test**: 提供分析结果数据，调用报告生成器，验证输出 Markdown 文件包含结构化报告（标题、元数据、表格），Excel 文件包含正确格式的表格数据。

**Acceptance Scenarios**:

1. **Given** 模版分析结果已生成，**When** 系统生成 Markdown 报告，**Then** 报告包含：标题（含日期范围）、汇总统计（总销售额、总人数、总门店数）、详细分析表格（与模版格式一致）。
2. **Given** 模版分析结果已生成，**When** 系统生成 Excel 文件，**Then** Excel 包含正确格式的数据表格（表头加粗、数字列右对齐、保留两位小数）。
3. **Given** 分析期间内有 0 销售额的员工，**When** 生成报告，**Then** 报告中 0 销售额员工单独标注但不从报告中剔除。

---

### User Story 4 - 多模版管理与切换 (Priority: P3)

作为系统管理员，我希望能够注册多个分析模版（YAML/JSON配置），在导出时选定目标模版，系统按选定模版执行对应的分析逻辑，模版之间互不干扰。

**Why this priority**: 在单模版验证通过后，多模版支持使系统能服务于多种业务场景。

**Independent Test**: 注册两个不同结构（列定义、分组维度不同）的分析模版，分别对同一份导出数据执行分析，验证两份结果按各自的模版结构正确输出。

**Acceptance Scenarios**:

1. **Given** 系统中注册了"三诊九体培训动销"和"月度销售汇总"两个模版，**When** 分别选定两个模版执行分析，**Then** 两份分析结果按各自模版定义的结构输出，互不污染。
2. **Given** 新增了一个分析模版配置文件，**When** 系统重新加载模版注册表，**Then** 新模版立即可用，无需重启服务。
3. **Given** 模版配置文件包含模版名称、列定义、分组规则、排序规则和汇总规则，**When** 系统解析模版，**Then** 所有字段正确解析并可被分析引擎使用。

---

### Edge Cases

- 导出数据量超过 10 万行时，系统如何保证内存不溢出？（假设：采用流式/分批处理）
- SQL Server 查询超时（默认 30 秒）时的退避策略？
- 员工 ID 在不同门店中可能重复（同一员工调店），模版匹配时以门店+员工ID为唯一键？
- 模版中定义的分组维度在数据中缺失对应字段时如何处理？
- 日期范围跨越多月时，分析结果是否需要增加月份分组？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持从 YAML/JSON 配置文件读取 SQL Server 连接参数（服务器地址、端口、数据库名、用户名）和查询语句。密码字段 MUST 使用 `${ENV_VAR}` 环境变量引用，禁止明文密码。
- **FR-002**: 系统 MUST 支持 SQL 查询参数化，包括但不限于：日期范围、企业ID、商品ID列表、员工ID列表。
- **FR-003**: 系统 MUST 将 SQL 查询结果导出为 .xlsx（UTF-8）格式。
- **FR-004**: 系统 MUST 支持通过 YAML 配置文件定义分析模版，模版包括：模版名称、列定义、分组维度、排序规则、汇总规则。
- **FR-005**: 系统 MUST 按模版定义的维度（片区→门店→员工）对导出数据进行分组汇总，计算每个员工的汇总销售金额。
- **FR-006**: 系统 MUST 计算每个员工的销售占比（员工销售额 / 总销售额 × 100%）和合计行的总计值。
- **FR-007**: 系统 MUST 将模版分析结果导出为 Markdown 格式的分析报告和 Excel（.xlsx）文件。
- **FR-008**: 系统 MUST 在每次分析完成后生成分析元数据（执行时间、数据条数、模版名称、匹配率等）并记录日志。
- **FR-009**: 系统 MUST 支持注册和管理多个分析模版，模版之间独立配置、互不影响。
- **FR-010**: 系统 MUST 在模版匹配时同时处理"模版有但数据无"（销售额为0）和"数据有但模版无"（附加行单独列出，不计入合计行和总销售额）两种情况。
- **FR-011**: 系统 MUST 通过 CLI 命令触发全流程：导出 → 分析 → 报告生成，支持 `--template` 参数指定模版名称。
- **FR-012**: 系统 MUST 使用参数化查询（Prepared Statements）防止 SQL 注入。

### Key Entities

- **ExportConfig（导出配置）**: SQL Server 连接参数、查询语句文本、参数字典、导出格式（.xlsx）。
- **AnalysisTemplate（分析模版）**: 模版名称、列定义（列名、数据来源字段、格式化规则）、分组维度列表、排序规则、汇总规则（合计、占比计算）。
- **ExportResult（导出结果）**: 原始查询返回的数据行集合、导出时间戳、记录数、导出文件路径。
- **AnalysisResult（分析结果）**: 按模版分组汇总后的数据行集合、合计行、占比计算值、未匹配数据行列表、分析元数据（执行时间、匹配率）。
- **AnalysisReport（分析报告）**: Markdown 格式文本（含标题、元数据、表格）、Excel 文件路径、生成时间戳。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 系统在 30 秒内完成 5000 行以内数据的导出和模版分析全流程。
- **SC-002**: 分析结果中销售额合计行与 SQL 直接查询的总销售额偏差为 0（精确匹配）。
- **SC-003**: 模版中定义的每个员工的销售金额与 SQL 逐员工查询结果一致（逐行精确验证）。
- **SC-004**: 系统支持同时注册和管理至少 10 个不同的分析模版。
- **SC-005**: 分析报告 Markdown 和 Excel 文件生成后可直接打开阅读/编辑，无需额外处理。
- **SC-006**: 配置或 SQL 语句错误时，系统能在 5 秒内返回明确的错误信息（而非崩溃或挂起）。
- **SC-007**: 100% 的模版定义员工都能在分析结果中找到对应行（匹配覆盖率 100%）。

## Assumptions

- SQL Server 数据库可通过内网直接访问，网络延迟在可接受范围内（<100ms）。
- 数据量级当前在 10 万行以内，暂不需要分布式计算框架。
- 分析模版的业务语义（如"三诊九体"的含义）仅影响模版内容定义，不影响系统核心分析逻辑。
- 模版中员工与门店的映射关系在模版配置文件中预定义，系统不负责自动推断映射。
- 占比计算的基数（总销售额）通过单独的汇总 SQL 查询获取，与明细查询在同一配置中定义。
- 技术实现语言优先考虑 Python 3.11+，利用 pandas 进行数据处理，openpyxl 生成 Excel，PyMSSQL 连接 SQL Server。
- 所有配置文件和输出文件使用 UTF-8 编码。
- 日期范围以天为最小粒度（格式：YYYY-MM-DD）。

- Q: 数据库密码是否允许在YAML配置中明文存储？ → A: 强制使用 `${ENV_VAR}` 环境变量引用，拒绝纯文本密码
