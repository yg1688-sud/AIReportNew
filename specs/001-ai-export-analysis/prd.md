## 1. 产品概述

### 1.1 产品背景

当前业务团队需要定期从 SQL Server 数据库中导出销售明细数据，并按照"三诊九体培训动销及打卡学习情况"等业务模版进行人工分析。该流程存在以下痛点：

- **手工操作耗时**：每次导出需要在 SQL 工具中执行多条查询，将结果复制到 Excel 中手动整理
- **模版匹配繁琐**：数据中有 60+ 名员工、30+ 个门店，需要逐行匹配到模版格式
- **容易出错**：手工计算占比、合计、排序，容易遗漏或计算失误
- **不可复用**：每次分析都要重复完整流程，切换模版需要重新开始

### 1.2 产品价值

AIExport 将"数据导出 → 模版匹配 → 分析计算 → 报告生成"全流程自动化，将原先耗时 1-2 小时的人工操作缩短至 30 秒以内，同时消除人工计算错误。

### 1.3 目标用户

| 角色 | 需求 | 使用频率 |
|------|------|----------|
| 业务分析师 | 按模版生成销售分析报告 | 每日/每周 |
| 区域经理 | 查看本区域员工的销售表现 | 每周 |
| 系统管理员 | 配置数据源、新增分析模版 | 按需（低频） |

## 2. 业务流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 1.配置    │───▶│ 2.导出    │───▶│ 3.分析    │───▶│ 4.报告    │
│ 数据源    │    │ 原始数据  │    │ 模版匹配  │    │ 生成输出  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
     │               │               │               │
     ▼               ▼               ▼               ▼
 config.yaml     data/*.csv     模版计算+汇总    report/*.md
                 data/*.json    匹配+占比       report/*.xlsx
```

**步骤说明**：

1. **配置阶段**：系统管理员在 YAML 配置文件中定义 SQL Server 连接参数、查询语句、分析模版
2. **导出阶段**：系统连接数据库，执行参数化查询，将结果保存为 CSV/JSON 文件
3. **分析阶段**：系统读取导出的原始数据，按选定模版的维度（片区→门店→员工）进行分组汇总，计算销售金额和占比，处理匹配和不匹配的数据
4. **报告阶段**：系统将分析结果格式化为 Markdown 报告和 Excel 表格，输出到指定目录

## 3. 功能需求（用户视角）

### 3.1 配置化数据导出

**用户故事**: 作为系统管理员，我只需编辑一个配置文件，就能定义数据源和查询语句，无需编写代码。

**功能点**:
- SQL Server 连接配置（服务器、端口、库名、凭证）
- 查询语句定义（支持参数化：日期范围、企业ID、商品列表、员工列表）
- 输出格式选择（CSV + JSON 双格式）
- 配置校验：启动时检查配置完整性，错误时给出具体提示

### 3.2 模版化数据分析

**用户故事**: 作为业务分析师，我选择一个分析模版，系统自动将导出的数据按模版格式整理好。

**功能点**:
- 模版注册：YAML 文件定义模版结构（列、分组、排序、汇总规则）
- 数据匹配：按门店+员工维度匹配模版中的行定义
- 汇总计算：小计（片区级）、合计（全连锁）、占比（员工/连锁总额）
- 兼容处理：
  - 模版有但数据无 → 销售额为 0，保留行
  - 数据有但模版无 → 附加行列出，记录日志
- 多模版互不干扰

### 3.3 报告生成

**用户故事**: 作为区域经理，我收到系统自动生成的 Markdown 分析报告和 Excel 表格。

**功能点**:
- Markdown 报告：包含标题（含日期范围）、汇总统计卡片、详细分析表格
- Excel 报告：格式化的表格（表头加粗、数字右对齐、两位小数）
- 分析元数据：执行时间、数据行数、模版名称、匹配率

### 3.4 CLI 一键执行

**用户故事**: 作为业务分析师，我在终端执行一条命令即可完成导出→分析→报告全流程。

**功能点**:
- `ai-export run --template <模版名>`：一键执行全流程
- `ai-export export`：仅执行数据导出
- `ai-export analyze --template <模版名>`：仅执行分析
- `ai-export list-templates`：列出所有可用模版
- `ai-export validate`：校验所有配置文件

## 4. 非功能需求

| 类别 | 需求 | 指标 |
|------|------|------|
| 性能 | 中等数据量快速处理 | 5000 行数据全程 < 30 秒 |
| 可靠性 | 数据精确一致 | 合计值与 SQL 查询结果偏差为 0 |
| 可维护性 | 配置驱动 | 新增模版无需修改代码 |
| 安全性 | SQL 注入防护 | 参数化查询（Prepared Statements） |
| 可观测性 | 过程可追踪 | 每步日志记录（输入/输出/耗时） |
| 兼容性 | 输出格式通用 | UTF-8 编码、CSV/JSON/Excel/Markdown |

## 5. 成功指标（KPI）

| 指标 | 当前基线 | 目标值 | 衡量方式 |
|------|---------|--------|----------|
| 分析耗时 | 1-2 小时（人工） | < 30 秒（自动） | 系统日志计时 |
| 数据准确率 | ~95%（人工易错） | 100%（精确匹配） | 与 SQL 直查比对 |
| 模版匹配覆盖率 | N/A | 100% | 模版员工全匹配 |
| 模版扩展效率 | 需开发介入 | 纯配置即可新增 | 新增模版耗时 < 5 分钟 |
| 错误恢复时间 | 不可恢复 | 5 秒内返回明确错误 | 错误信息返回耗时 |

## 6. 风险与依赖

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| SQL Server 不可达 | 导出失败 | 连接超时 + 明确错误提示 + 重试机制 |
| 大数据量内存溢出 | 系统崩溃 | 流式/分批处理 + 数据量预估日志 |
| 模版定义错误 | 分析结果错误 | 配置校验 + 模版格式 schema 验证 |
| 员工跨店导致重复 | 匹配错乱 | 以门店+员工ID为唯一匹配键 |

**外部依赖**:
- SQL Server 数据库网络可达
- 数据库账号具有只读查询权限
- Python 3.11+ 运行环境
